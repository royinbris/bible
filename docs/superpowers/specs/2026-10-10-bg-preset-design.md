# 배경색 프리셋 설정 — 설계

- 일자: 2026-10-10
- 상태: 사용자 승인됨
- 범위: 앱 전체 · 프리셋 5종 · 프리셋이 라이트/다크 테마보다 우선

## 1. 목표

설정 모양 탭에서 앱 전체 배경색을 고를 수 있게 한다. 종이 질감 라이트 계열
프리셋만 제공하므로 다크모드 대비 깨짐이 없도록 한다.

## 2. 데이터

- `user_settings.bgPreset` 신규 키. 값: `'default'`(기본, 현재 동작 그대로) |
  `'cream'` | `'sepia'` | `'green'` | `'gray'`.
- 기존 저장값에 키가 없으면 `'default'`로 간주한다. 기존 사용자 화면 변화 없음.
- `user_settings`는 이미 기기 간 동기화 대상이므로 동기화 작업 불필요.
  (한 기기에서 고르면 다른 기기에도 동일 적용됨)

## 3. 적용 방식

- `SettingsContext`의 기존 테마 적용 `useEffect`를 확장한다.
- `bgPreset === 'default'`: 기존 동작 그대로 (`data-theme`만 설정, `data-bg` 제거).
- 그 외: `data-theme`을 강제로 `'light'` 고정 + `<html data-bg="<preset>">` 설정.
  - 이유: 프리셋이 전부 라이트 종이색이므로, 다크 전용 분기(FileView의
    `isDarkTheme` 등)가 크림 배경에 어긋나는 일을 원천 차단한다.
  - 다크 계열 프리셋이 필요해지면 그때 `data-theme` 강제값을 재설계한다
    (본 스펙 범위 밖).

## 4. CSS

- `app/src/index.css`의 테마 블록 뒤에 `[data-bg='<preset>']` 블록을 둔다
  (우선 적용 보장).
- 프리셋마다 재정의하는 변수: 배경(`--bg-color`), 보조배경(`--secondary-bg`),
  글자(`--text-color`), 테두리(`--border-color`, `--nav-border`) 4~6개.
- 그 외 변수(강조색 등)는 라이트 테마 값을 그대로 상속한다.

## 5. UI

- 설정 시트 모양 탭에 스와치 버튼 5개(기본·크림·세피아·그린·그레이).
- 선택 즉시 `updateSetting('bgPreset', ...)` → 전역 즉시 반영, 별도 저장 버튼 없음
  (기존 모양 탭 패턴과 동일).

## 6. 에러 처리

- `localStorage` 파싱 실패 시 기존 `SettingsContext` 폴백(DEFAULT_SETTINGS +
  `bgPreset: 'default'`)을 따른다. 유효하지 않은 값은 `'default'`로 정규화한다.

## 7. 테스트

- `npm run build` 통과.
- 프리뷰에서 5종 전환 시 전체 화면 변수_override 육안 확인.
- 다크모드 기기에서 프리셋 선택 시 어긋남(흰 글씨 on 크림 배경 등) 없는지 확인.
- 기기 간 동기화 후 상대 기기에도 동일 배경 적용되는지 확인.

## 8. 범위 밖

- 다크 계열 배경 프리셋, 임의 색상 컬러피커, 화면별 개별 배경.
