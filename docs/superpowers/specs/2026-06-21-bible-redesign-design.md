# 한국어 가톨릭 성경 앱 — 전면 재디자인 설계

작성일: 2026-06-21

## 목표

앱 전체를 "고요한 영성" 무드로 전면 재디자인한다. 시각 시스템(색·타이포·여백·카드)을
새로 정의하고, 과도하게 복잡해진 하단 네비게이션을 단순화한다. 정보 구조(홈/성경/미사/기도)는
유지한다.

## 디자인 방향: A · 따뜻한 종이

- 크림빛 종이 질감 배경, 세리프 제목/본문, 점토색(clay) 포인트
- 라이트 = 따뜻한 종이, 다크 = 어두운 성소(깊은 차콜 + 은은한 금)
- 기존 `data-theme` 라이트/다크 토글(시스템/라이트/다크)을 그대로 유지하되 팔레트를 교체

## 1. 디자인 토큰

### 타이포그래피

- 본문/제목 세리프: `--serif-font: 'Noto Serif KR', 'Nanum Myeongjo', serif` (이미 로딩됨)

- 성경 본문은 세리프, 줄간격 기본 2.0~2.15 (기존 `settings.lineHeight` 사용자 설정 유지)

"고요한" 무드를 유지한다. (필요 시 미사/기도/한권읽기를 점토의 명도 변주로 구분)

## 2. 읽기 화면 (Reader) — 앱의 핵심

**이 앱의 핵심은 "성경 전체가 한 권으로 끊김 없이 연결되어 스크롤"되는 것이다.**
장을 페이지로 끊어 넘기지 않는다. 모든 장이 하나의 연속된 본문으로 이어지며, 계속
스크롤하면 다음 장이 자연스럽게 따라온다(현재 Reader의 `loadMoreNext`/`loadMorePrev`
무한 스크롤 동작을 유지·강화).

- 본문: 세리프, 줄간격 넉넉(2.0~2.15), 종이결 배경
- 절 번호: 작은 점토색 위첨자(`--accent-soft`), 본문 흐름 유지
- 장 경계: 끊김이 아니라 연속 흐름 속의 **표시**. 큰 장 번호(`--chapter-num`) +
  책 이름 캡션을 가운데 배치하되, 위아래 본문이 그대로 이어지도록 함
- 소제목: 가운데 정렬, 점토색, 차분하게
- 절 선택 모드: 상단 점토색 액션바(복사·공유·형광펜), 형광펜은 `--highlight`
- 읽기 중 하단: **"이전/다음 장" 같은 장 분리 네비게이션을 두지 않는다**(핵심에 어긋남).
  몰입을 위해 스크롤 시 하단바 자동 숨김(현재도 스크롤 연동). 듣기·필사 등 액션만 최소 노출.

기존 클래스(`.verse`, `.verse-num`, `.reader-subheading`, `.chapter-title`,
`.reader-container`, `.reader-header-v2`)의 스타일을 위 토큰으로 재정의.

### 설정 항목은 모두 유지 (중요)

설정 시트의 모든 조절 항목을 그대로 유지한다: 테마 모드 · 성경 언어 · 글자 크기 ·
글자 두께 · 줄 간격 · 구절 간격 · 좌우 여백 · 글꼴. 재디자인이 바꾸는 것은 **기본값과
시각 처리뿐**이며, 사용자가 설정한 값이 항상 기본값보다 우선한다.

- 세리프 본문 = 새 기본 글꼴. 글꼴 설정에서 다른 글꼴 선택 시 그대로 적용.
- 줄간격 2.0~2.15 = 새 기본값. 줄 간격 휠로 조절 가능.
- 위첨자 절번호 = 절번호의 시각 표시 방식(기존에도 설정 항목 아님). 디자인 사항.
- 연속 스크롤(모든 장 연결)은 앱의 핵심 동작이며 설정 항목이 아니다. 항상 적용.

## 3. 네비게이션 단순화

### 문제

`App.jsx`의 `GlobalBottomBar`가 약 1,200줄(227~1450). 화면마다 좌/우 바로가기 버튼이
바뀌고, 플로팅 FAB, 시트, 오버레이가 한 컴포넌트에 얽혀 유지보수가 어렵고 사용자에게
일관성이 없다.

### 해결

- **4탭 고정 바**: 홈 · 성경 · 미사 · 기도. 어느 화면에서나 동일 위치. 현재 라우트
  기준 활성 탭 표시.
- **검색·설정**: 하단바에서 분리해 각 화면 상단 우측 아이콘으로 이동.
- **읽기 화면 예외**: Reader에서는 연속 스크롤 몰입을 위해 스크롤 시 하단바를 자동
  숨김. 장 분리 네비게이션은 두지 않는다(연속 연결이 핵심).
- 아이콘은 현재 앱의 SVG 아이콘 스타일을 유지(예시 아이콘은 시안용).

### 컴포넌트 분리

거대한 `GlobalBottomBar`를 다음으로 분리한다:

- `BottomTabBar` — 4탭 고정 바(라우트 기반 활성 상태). 작고 한 가지 책임.
- `ReaderActionBar` — 읽기 화면 전용 장 이동/액션 바.
- 화면 상단 액션(검색/설정)은 각 페이지 헤더 또는 공용 `ScreenHeader`로.

각 단위는 단독으로 이해·테스트 가능해야 한다. 라우트 변경에 따른 활성 탭 계산은
`useLocation` 기반 순수 함수로 분리.

## 4. 적용 범위 / 비범위

### 범위

- `src/index.css` 팔레트·타이포 토큰 전면 교체 (라이트+다크)
- 인라인 하드코딩 색상 → 변수 치환 (홈/미사/기도/검색/한권읽기/읽기 화면)
- 읽기 화면 시각 재설계
- 하단 네비게이션 단순화 및 컴포넌트 분리

### 비범위 (이번에 건드리지 않음)

- 데이터 로직(미사 API, 한권읽기 일정 계산, TTS, localforage 저장 구조)
- 라우트 경로 자체(홈/성경/미사/기도 화면 종류와 URL 유지)
- 기능 추가(새 화면·새 기능 없음). 순수 디자인·구조 개선.

## 5. 성공 기준

- 라이트/다크 양쪽에서 모든 화면이 새 팔레트로 일관되게 렌더링되고 가독성 확보
- 읽기 화면이 세리프·위첨자 절번호·넉넉한 줄간격으로 시안과 일치
- 읽기 화면에서 모든 장이 끊김 없이 하나로 연속 스크롤됨(핵심 동작 유지)
- 하단바가 모든 화면에서 동일한 4탭으로 고정(읽기 화면만 스크롤 시 자동 숨김)
- `GlobalBottomBar` 단일 1,200줄 컴포넌트가 작은 단위로 분리됨
- 기존 사용자 설정(글꼴/크기/줄간격/언어/테마)·기능이 그대로 동작
